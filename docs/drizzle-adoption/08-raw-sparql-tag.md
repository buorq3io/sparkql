# 08: Raw `sparql` template tag

Kind: feature. Size: M. Read [README.md](README.md) first.

## Goal

An escape hatch for SPARQL that sparkql's helpers and dialects do not cover
(a vendor function, an unusual pattern) that still composes with the builder:

```ts
const score = sparql<number>`<http://example.org/fn#score>(${v.doc}, ${'query text'})`;
db.select({ s: as(score, v.s) }).where(sparql.pattern`?doc <http://ex/p> ?o . hint:Query hint:optimize "none" .`);
```

Interpolated values are serialised as safe RDF terms (variables, IRIs,
literals through the database's formatters); only text written inside the
template literal is emitted verbatim.

## sparkql today (verified)

- No raw input path. Every node must be a known Traqula AST shape, or a custom
  pattern recognised by the active dialect (`src/database/dialect.ts`
  `patterns.is`/`normalize`, generated by the dialect's Traqula generator).
- `docs/dialects.md` states custom _expression_ node kinds are not supported.
  `sanitizeExpression` in `src/database/sparql-query.ts` throws
  `Unsupported expression provided.` for unknown kinds.
- Typed results already exist: expressions carry a `transform`
  (`src/helpers/types.ts` `TransformExpression`), applied by `as()` and
  `castX()` in `src/structures/expression.ts`.

## Design direction

- **Two node kinds:** a raw _expression_ (usable anywhere an
  `ExpressionInput` is) and a raw _pattern_ (usable in `where()`, `optional()`,
  etc.). Each holds string parts and interpolated values.
- **Normalisation:** interpolated values normalise through the existing paths
  (`sanitizeExpression` / term formatters), so `${'text'}` becomes a literal and
  `${v.x}` a variable. Nested raw nodes compose.
- **Generation:** this needs Traqula generator support for the new nodes in the
  standard generator _and_ the ARQ/Stardog generators
  (`src/arq/generator.ts`, `src/stardog/`). Follow the copy-then-patch approach
  in `docs/dialects.md`; do not mutate shared Traqula builders. First check
  whether Traqula already has a verbatim/raw node you can reuse.
- **Typing:** `sparql<T>\`...\`` sets the result type; `.mapWith(transform)`
  attaches a `TermVariableTransform`, consistent with `castX`.
- **Unsafe path:** a separate, clearly named `sparql.raw(string)` for text with no
  interpolation. The tag itself never splices a JS string as text.
- The pattern-extension seam in `dialect.ts` remains the recommended route for
  reusable vendor features; document the raw tag as the one-off escape hatch.

## Done when

- Raw expressions work in SELECT projection, FILTER, BIND, ORDER BY and GROUP BY;
  raw patterns work at top level and inside OPTIONAL/UNION/GRAPH; in the
  standard, ARQ and Stardog databases.
- Tests prove interpolated strings with quotes, newlines and `}` are emitted as
  escaped literals, never as SPARQL text.
- Type-level tests: `sparql<number>` projects to `number`, `.mapWith` changes it.
- `docs/` gains a section on when to use the tag versus a dialect.
